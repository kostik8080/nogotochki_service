# Клиентский интерфейс «Ноготочки»

Страницы для клиента и гостя: лендинг, вход и регистрация, личный кабинет, шаги записи. Каркас раздела администратора — `admin/`. Обычные HTML, CSS и JavaScript без сборщиков и фреймворков: файлы из этой папки браузер получает как есть. Правила верстки — [docs/frontend-rules.md](../docs/frontend-rules.md), что показывает каждый экран и откуда берет данные — [docs/ui-map.md](../docs/ui-map.md).

Черновой фронтенд для ручной проверки API (React) — в [web-draft/](../web-draft/README.md), к этой папке он не относится.

## Запуск

Нужен запущенный сервер API (`server/README.md`), затем из корня проекта:

```bash
node tools/web-dev-server.mjs
```

Откройте **http://127.0.0.1:8090**. Сервер отдает файлы из `web/` и передает запросы `/api` серверу API на порту 3000: для браузера это один адрес, поэтому cookie сессии работает без CORS. `npm install` здесь не нужен — зависимостей нет. Другие порты: `PORT=8091 API_URL=http://127.0.0.1:3001 node tools/web-dev-server.mjs`.

## Страницы

| Файл | Экран карты | Что это |
|---|---|---|
| `index.html` | PUB-01 | Лендинг: услуги, мастера и работы из API |
| `login.html` | AUTH-01 | Вход; `?next=страница.html` — куда вернуть после входа |
| `register.html` | AUTH-03, AUTH-02 | Регистрация; код из письма (сценарий 16) — шаг этой же страницы |
| `forgot-password.html` | AUTH-06 | Запрос ссылки для нового пароля |
| `reset-password.html` | AUTH-08 | Новый пароль по ссылке из письма (`/reset-password?token=…`) |
| `account.html` | CAB-01 | Мои записи |
| `history.html` | CAB-02 | История: прошедшие и отмененные визиты |
| `booking.html` | CAB-03, CAB-05 | Карточка записи; отмена — окно на этой странице (`?cancel=1` — открыть сразу) |
| `profile.html` | CAB-07, CAB-10, AUTH-02 | Профиль, три вкладки: «Личные данные» (имя, телефон только для чтения, e-mail с кодом из письма — окно на этой странице), «Безопасность» (пароль, выход, удаление аккаунта — окно с паролем), «Уведомления» (согласие на новости). `#security`, `#notifications` — открыть вкладку |
| `booking-services.html` | BOOK-01 | Запись, шаг 1: услуги |
| `booking-master.html` | BOOK-02 | Запись, шаг 2: мастер |
| `booking-time.html` | BOOK-03, CAB-04 | Запись, шаг 3: дата и время, бронь на 10 минут; с `?reschedule=ID` — перенос записи |
| `booking-confirm.html` | BOOK-04 | Запись, шаг 4: удержание времени с таймером, подтверждение |
| `booking-success.html` | BOOK-05 | Вы записаны: детали визита, файл для календаря |
| `admin/bookings.html` | A-01 | Раздел администратора, «Записи» — адрес `/admin`. Пока пустая страница |
| `admin/services.html` | A-23 | «Услуги» — `/admin/services`. Пока пустая страница |
| `admin/masters.html` | A-19 | «Мастера» — `/admin/masters`. Пока пустая страница |
| `forbidden.html` | — | «Этот раздел только для администраторов»: сервер отдает ее с кодом 403 клиенту и мастеру на адресах `/admin…` |

Еще не сверстаны, но на них уже ведут ссылки (адреса — в `js/routes.js`): `master.html`, `privacy.html`.

**Раздел администратора** (`/admin`) — пока каркас: шапка, меню «Записи», «Услуги», «Мастера» и пустые страницы. Вход — общая форма `login.html`: после входа администратора ведет в `/admin`, клиента — в кабинет. Страницы `admin/` отдает не этот сервер, а сервер API после проверки роли: гостю — вход, клиенту и мастеру — 403 и `forbidden.html` (`server/src/web/admin-pages.ts`). `tools/web-dev-server.mjs` передает `/admin` серверу API и файлы `admin/` напрямую не отдает. Расписание мастера и сами экраны раздела пока есть только в черновом интерфейсе [web-draft/](../web-draft/README.md). Какие эндпоинты использует каждый экран и что чинили по ходу верстки — [docs/frontend-log.md](../docs/frontend-log.md).

## Как устроено

| Где | Что |
|---|---|
| `tokens.css` | Цвета, шрифты, размеры и отступы. Других значений в стилях нет |
| `css/base.css` | Сброс, контейнер, кнопки, заглушки загрузки, подвал |
| `css/header.css`, `js/header.js` | Общая шапка `<client-header>`: логотип, «Записаться», колокольчик, меню аккаунта или «Войти» |
| `js/notifications.js` | Колокольчик уведомлений: сообщения студии об отмене и переносе записи и напоминания о визите за сутки, 2 часа и 15 минут; счетчик, закрытие ✕ |
| `js/dropdown.js` | Выпадающий список по кнопке: меню аккаунта, меню гостя, уведомления |
| `css/cabinet.css`, `js/cabinet-nav.js` | Каркас кабинета и его меню `<cabinet-nav>` |
| `js/booking-steps.js` | Индикатор шагов записи `<booking-steps current="…">` |
| `js/api.js` | Все запросы к серверу — только здесь |
| `js/store.js` | Черновик записи (услуги, мастер, время) в `sessionStorage` вкладки |
| `js/routes.js` | Адреса страниц |
| `js/calendar.js` | Файл `.ics` «Добавить в календарь» |
| `js/format.js`, `js/form.js` | Деньги, длительность, даты в часовом поясе студии; проверка полей и ошибки форм |
| `js/roles.js` | `hasRole(user, 'admin')` — есть ли роль в списке `user.roles`. Только решает, что показать: доступ закрывает сервер |
| `css/admin.css`, `js/admin.js` | Каркас раздела администратора: меню `<admin-nav>`, проверка роли на странице, сообщение «Этот раздел только для администраторов» |

> **До публикации замените `img/hero.jpg`.** Это временная заглушка для фона первого экрана лендинга: фото взято из чужого референса «LUXE», текст с него убран нейросетью, прав на него у студии нет. Нужно свое фото работы мастера или фото со свободной лицензией. Подойдет горизонтальное фото: рука справа на темном фоне, слева пусто. Положите его под тем же именем — стили менять не нужно (`css/landing.css`, переменная `--hero-photo`).

У каждой страницы свой CSS и свой скрипт с тем же именем (`booking-time.html` → `css/booking-time.css`, `js/booking-time.js`).
