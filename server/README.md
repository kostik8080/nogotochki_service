# Сервер «Ноготочки»

Node.js 24.7+ и TypeScript, база SQLite через встроенный модуль `node:sqlite`. Схема базы — `docs/db-schema.md`.

## Первый запуск

```bash
cd server
npm install
cp .env.example .env     # заполнить SEED_ADMIN_PASSWORD и SEED_CLIENT_PASSWORD
npm run db:reset         # создать базу data/nogotochki.db с тестовыми данными
```

## Команды

| Команда | Что делает |
|---|---|
| `npm run db:migrate` | Создает файл базы, если его нет, и применяет новые миграции |
| `npm run db:seed` | Заполняет пустую базу тестовыми данными |
| `npm run db:reset` | Удаляет файл базы и создает заново: миграции + тестовые данные |
| `npm run db:check-schema` | Сверяет базу, которую строят миграции, с `docs/db-schema.md`: таблицы, поля, типы, ключи, индексы |
| `npm run admin:create` | Создает учетную запись администратора: имя, логин и пароль спрашиваются при запуске |
| `npm run build` | Сборка для production в `dist/`: код и SQL-миграции, без тестовых данных |
| `npm run prod:migrate` | То же, что `db:migrate`, из сборки `dist/` |
| `npm run prod:admin:create` | То же, что `admin:create`, из сборки `dist/` |
| `npm run typecheck` | Проверка типов TypeScript |

Тестовые входы: администратор `admin@example.com`, клиентка `maria@example.com` (пароли — из `.env`).

## Миграции

Файлы `src/db/migrations/NNN_description.sql` применяются по порядку номеров, каждый один раз. Примененную миграцию не правят (сервер это заметит по контрольной сумме): изменение схемы — новый файл со следующим номером.

## Выкладка на сервер

На сервере нужен только Node.js 24.7 или новее (рекомендуется последняя 24.x — ветка с долгосрочной поддержкой). Больше ничего: база работает через встроенный модуль `node:sqlite`, а хеширование паролей — через встроенный `node:crypto`, поэтому у сборки нет зависимостей и нативных модулей, которые пришлось бы компилировать на хостинге. Проверить версию: `node -v`.

Версию 24.7 задают две возможности Node: `argon2` в `node:crypto` (появился в 24.7) и `node:sqlite` без флагов. В ранних выпусках 24.x при запуске может печататься `ExperimentalWarning` про SQLite — это предупреждение, а не ошибка.

В окружении production обязательно:

* `NODE_ENV=production`;
* `DATABASE_PATH` — абсолютный путь вне папки с кодом, например `/var/lib/nogotochki/nogotochki.db`. Папку с кодом заменяют при обновлении, база внутри нее пропала бы.

С неверными настройками команды не запускаются и пишут, что исправить. Тестовые данные в production не загружаются.

Первая выкладка:

```bash
npm ci                    # точные версии из package-lock.json
npm run build
npm prune --omit=dev      # убрать TypeScript и tsx, они нужны только для сборки
npm run prod:migrate      # создать базу: схема, настройки и режим работы студии
npm run prod:admin:create # учетная запись владельца студии
```

Новая база стартует в режиме технических работ (`settings.is_maintenance = 1`): адрес и телефон в ней взяты из прототипа. Администратор вносит настоящие контакты и выключает режим — тогда клиенты видят запись. Раздела настроек пока нет (он появится вместе с API), до этого — запросом `UPDATE settings SET address = …, phone = …, is_maintenance = 0 WHERE id = 1`.

Обновление — те же `npm ci`, `npm run build`, `npm prune --omit=dev`, `npm run prod:migrate`. Каждая миграция выполняется в своей транзакции: если она упадет, база останется прежней.
