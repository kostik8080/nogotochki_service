# Тестовый фронтенд «Ноготочки»

Черновой интерфейс для ручной проверки API (`docs/api.md`): обычные формы, таблицы и кнопки, минимум стилей. Это не дизайн сервиса — экраны прототипа (`Prototype/`) использованы только как перечень того, что нужно каждой роли. Ошибки API показываются на странице: текст сервера, код (`SLOT_TAKEN`, `VALIDATION_ERROR`…), ошибки полей и ближайшее свободное время, если слот занят. Под каждым списком есть сырой ответ API (JSON).

Экраны клиента — каталог, регистрация и «Мои записи» — отсюда убраны: их заменил клиентский интерфейс [web/](../web/README.md). Остались вход, запись (ею пользуется администратор), карточка записи, раздел администратора и расписание мастера.

React + Vite + TypeScript. Запросы идут на `/api` того же адреса, Vite проксирует их на API (`http://127.0.0.1:3000`), поэтому cookie сессии работает без CORS.

## Запуск

```bash
cd server && npm start       # API на http://localhost:3000
cd web-draft && npm install
npm run dev                  # интерфейс на http://127.0.0.1:5173
```

Тестовые входы — те же, что у сервера (`server/README.md`): администратор `admin@example.com`, мастер `anna@example.com`, клиентка `maria@example.com`, пароли — из `server/.env` (`SEED_*`).

## Страницы

| Адрес | Кто | Что проверяет |
|---|---|---|
| `#/login` | все | Вход по телефону или e-mail и паролю |
| `#/slots` | все | Свободное время мастера или «Любого свободного мастера» на дату. Клиент нажимает на время — создается бронь на 10 минут; занятое время — сообщение и ближайшие свободные слоты |
| `#/book` | клиент, администратор | Подтверждение записи: остаток брони, повторное закрепление после истечения, снятие брони. Администратор записывает без брони клиента из базы или нового клиента по имени и телефону, может ввести время вручную и отметить наложение |
| `#/bookings/:id` | владелец, мастер записи, администратор | Детали записи, перенос (клиент — по брони и до срока 24 часов), отмена с причиной; администратору — смена мастера, наложение, «Визит завершен» / «Клиент не пришел», история изменений |
| `#/admin` | администратор | Все записи с фильтрами; услуги (добавление, изменение, отключение, категории, несовместимые пары); мастера (добавление, уровень, услуги, отключение, новый график с проверкой затронутых записей, учетная запись мастера) |
| `#/master` | мастер | Свое расписание: рабочие часы, записи, блокировки — без контактов клиентов и цен |

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | Интерфейс с перезагрузкой при изменениях |
| `npm run build` | Проверка типов и сборка в `dist/` |
| `npm run typecheck` | Только проверка типов |
