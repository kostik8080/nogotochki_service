# Журнал подключения клиентских экранов

Что сверстано в `web/` к 29.09.2026 и откуда каждый экран берет данные. Составлено по коду `web/js/`, истории коммитов `bc1f69a`, `6651506`, `c26f72e`, `ab65e77` и отчетам сессий верстки 27–29.09.2026. ID и маршруты экранов — из [ui-map.md](ui-map.md) и прототипа `Prototype/Прототип - Ноготочки.dc.html`.

Все запросы идут через `web/js/api.js`. Ошибку API любой экран показывает текстом из `error.message`, а формы подсвечивают поля из `error.details.fields` (`js/form.js`). Время приходит в UTC и выводится в часовом поясе студии `timezone` из `GET /api/studio`, деньги — из копеек (`…Kop`).

## Вход и регистрация

**AUTH-01 Вход** — `#/login`
* **Файл:** `web/login.html`, `js/login.js`.
* **Показывает:** телефон или e-mail, пароль, ошибку входа; плашку «Войдите, чтобы закрепить время и завершить запись», если пришли с шага «Время».
* **Эндпоинты:** `POST /api/auth/login`; кнопка «Войти с Яндекс ID» — `POST /api/auth/yandex` (`js/yandex-login.js`).
* **Поля ответа:** `user.roles` — список ролей: администратор — в раздел `/admin` (или на его страницу из `?next=`), клиент — в кабинет (или на клиентскую страницу из `?next=`), мастер — на главную; коды `INVALID_CREDENTIALS`, `LOGIN_LOCKED` с заголовком `Retry-After`. Форма входа одна для всех: отдельного входа для сотрудников нет, ссылки «Вход для сотрудников» в подвале ведут сюда.
* **Вход через Яндекс** (добавлен 01.10.2026, настоящий Яндекс с 02.10.2026): кнопка под формой, в прототипе ее нет (ui-map, список 2, пункт 7). По нажатию — `GET /api/auth/yandex/start`: страница запоминает `state` и адрес возврата `?next=` в `sessionStorage` и уходит на страницу согласия Яндекса. Яндекс возвращает человека на `/login.html` с `?code=` и тем же `state`; страница сверяет `state` и отправляет код в `POST /api/auth/yandex`, дальше сервер сам ставит cookie сессии — токенов Яндекса страница не видит. Отказ на экране согласия (`?error=access_denied`) и ошибка Яндекса показываются плашкой «Вход через Яндекс не завершен…» на экране входа, адрес очищается от `code` и `error`. Ответ входа: `user` (как у входа по паролю), `registered` — создан аккаунт или это вход в существующий. Коды: `YANDEX_CODE_INVALID`, `YANDEX_NO_EMAIL`, `YANDEX_LOGIN_UNAVAILABLE`, `STAFF_PASSWORD_LOGIN_ONLY`, `ACCOUNT_BLOCKED` — текст сервера показывается в плашке карточки.
* **Оформление кнопки Яндекса** (03.10.2026): кнопка собрана не из дизайн-системы, а по требованиям Яндекса (`.ya-id-button` в `css/auth.css`, логотип — `web/img/yandex-id-logo.svg`): Яндекс запрещает менять цвет кнопки, толщину обводки и ее содержимое — текст, иконку и отступы между элементами внутри кнопки. Выбран вариант «дополнительная версия, светлая тема, размер L (48 px)», скругление — 4 px как у остальных кнопок и полей. Кнопка одинакова на AUTH-01 и AUTH-03. Пока браузер уходит в Яндекс и возвращается, кнопка только выключается (`disabled`, `aria-busy`), а ход входа показывает плашка карточки: менять текст кнопки нельзя.

**AUTH-03 Регистрация и AUTH-02 Код из письма** — `#/register`, `#/verify`
* **Файл:** `web/register.html`, `js/register.js`. Код из письма — шаг этой же страницы.
* **Показывает:** имя, телефон, e-mail, пароль, согласия; «Такой аккаунт уже есть» с «Войти»; шаг кода: «Код отправлен на …, действует … минут», оставшиеся попытки, повторная отправка через 60 секунд; при `delivery: studio` — «Позвоните в студию» с телефоном.
* **Эндпоинты:** `POST /api/auth/register` (без кода и с `code`), `GET /api/studio`; кнопка «Войти с Яндекс ID» — `POST /api/auth/yandex` (тот же `js/yandex-login.js`, что на AUTH-01: аккаунт создается без пароля и кода, дальше — как после обычной регистрации).
* **Поля ответа:** `status` (201 или 202), `delivery`, `sentTo`, `expiresInMin`; `details.attemptsLeft` у `INVALID_CODE`; коды `PHONE_TAKEN`, `EMAIL_TAKEN`; студия: `phone`.

**AUTH-06 Восстановление пароля** — `#/forgot-password`
* **Файл:** `web/forgot-password.html`, `js/forgot-password.js`.
* **Показывает:** поле «телефон или e-mail», затем «Проверьте почту» с телефоном студии для тех, у кого e-mail не указан; у аккаунта без пароля — карточка «Вход через Яндекс» (добавлена 01.10.2026).
* **Эндпоинты:** `POST /api/auth/password-reset/request`, `GET /api/studio`.
* **Поля ответа:** студия: `phone`; у 429 — `Retry-After`. Обычный ответ (202) экран не читает: он всегда одинаковый. Читается только `provider` и `message`: аккаунт с внешним входом (`provider: 'yandex'`) — письма нет, показывается текст сервера «вход выполняется через Яндекс» и кнопка на AUTH-01.

**AUTH-08 Новый пароль** — `#/reset-password`
* **Файл:** `web/reset-password.html`, `js/reset-password.js`. Открывается и по пути `/reset-password?token=…` из письма.
* **Показывает:** новый пароль и повтор; «Пароль изменен» или «Ссылка больше не действует».
* **Эндпоинты:** `POST /api/auth/password-reset/confirm`.
* **Поля ответа:** только код `INVALID_CODE` → «Ссылка больше не действует».
