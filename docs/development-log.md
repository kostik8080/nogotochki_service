## Настройки для запуска на сервере

Сервис запускается в контейнере (`Dockerfile` в корне проекта): контейнер собирается заново при каждом обновлении, и все, что лежало внутри него, стирается. Поэтому данные вынесены из образа в папку `/data`, которая подключается при запуске и живет сама по себе:

| Что | Где лежит | Из какой настройки берется |
|---|---|---|
| Файл базы | `/data/db/nogotochki.db` | `DATABASE_PATH` |
| Резервные копии | `/data/backups` | `BACKUP_DIR` |
| Фото работ | `/data/uploads` | `UPLOADS_DIR` |

Папки создаются сами при первом обращении, поэтому первый запуск на чистом сервере проходит без подготовки. Миграции применяет сам сервер при старте, до того как начнет отвечать (`src/db/auto-migrate.ts`); уже примененные второй раз не применяются.

Почти все это уже записано в [`docker-compose.yml`](../docker-compose.yml) в корне проекта: том для данных, порт, адрес сервиса и первый администратор. В панели сервера остается задать только то, что нельзя держать в репозитории, — пароль почты и ключи приложения Яндекса.

**Задать обязательно:**

| Переменная | Зачем |
|---|---|
| `APP_URL=https://topbrohuman.ru` | из него строятся ссылки в письмах; в production сервер требует `https://` и иначе не запускается |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `MAIL_FROM` | почта для восстановления пароля и подтверждения e-mail |
| `TRUST_PROXY=1` | если сервер стоит за прокси: иначе ограничение частоты запросов считает всех клиентов одним (в `docker-compose.yml` задано) |
| `YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET` | идентификатор и секрет приложения с https://oauth.yandex.ru — без них кнопка «Войти с Яндекс ID» отвечает «вход недоступен». Адрес возврата в приложении Яндекса — `APP_URL` + `/login.html` |
| `ADMIN_EMAIL` | адрес первого администратора: с ним сервер заведет учетную запись при первом запуске и напечатает пароль в журнал. В `docker-compose.yml` задан `admin@topbrohuman.ru` |
| подключение папки `-v /var/lib/nogotochki:/data` | не переменная, но без него данные пропадут при обновлении. Контейнер работает под пользователем с uid 1000, поэтому папке на хосте нужен тот же владелец: `chown -R 1000:1000 /var/lib/nogotochki` |

**Есть разумное значение по умолчанию, задавать не нужно:** `NODE_ENV` (`production` в образе), `PORT` (`3000`), `DATABASE_PATH` (`/data/db/nogotochki.db`), `BACKUP_DIR` (`/data/backups`), `UPLOADS_DIR` (`/data/uploads`), `WEB_DIR` (`../web` рядом с папкой сервера), `BACKUP_KEEP` (`14` копий), `PD_POLICY_VERSION` (`2026-09-01`).

**Можно не задавать:** `ADMIN_PASSWORD` — без него пароль первого администратора придумывается случайным и печатается в журнал сервера один раз, при создании учетной записи.

**Не задавать:** `SEED_ADMIN_PASSWORD`, `SEED_MASTER_PASSWORD`, `SEED_CLIENT_PASSWORD` — пароли тестовых данных, они тоже останавливают запуск.

Команды выкладки, сборка образа и резервные копии — в [`server/README.md`](../server/README.md).

## Что осталось за рамками

Сделано не будет в этой версии, вернуться можно в любой момент:

* перенос базы с SQLite на полноценную СУБД (PostgreSQL, как в паспорте продукта);
* уведомления по почте о записи, переносе и отмене — сейчас почта только для одноразовых кодов и ссылок;
* резервные копии по расписанию — сейчас `db:backup` запускается руками.
