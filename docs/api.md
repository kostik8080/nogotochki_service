# API «Ноготочки. Онлайн-запись»

REST API поверх базы из [`docs/db-schema.md`](db-schema.md). Код — `server/src/app.ts` и `server/src/api/`, тесты — `server/test/api.test.ts`. Запуск: `cd server && npm start` (порт `PORT`, по умолчанию 3000).

## Общие правила

| Что | Правило |
|---|---|
| Формат | Запросы и ответы — JSON. Тело запроса отправляется с `Content-Type: application/json`, иначе 415. |
| Время | Моменты времени — только UTC, ISO 8601 с `Z`: `2026-09-24T07:00:00.000Z`. Смещение пояса (`+03:00`) не принимается — 400. В ответах время тоже в UTC; в часовой пояс студии (`timezone` в ответе, `Europe/Moscow`) его переводит интерфейс при показе. Календарная дата студии — `YYYY-MM-DD` (параметр `date`). |
| Деньги | Целые копейки, поля `…Kop`: `180000` — это 1800 ₽. |
| Вход | Серверная сессия в cookie `nogotochki_session` (HttpOnly, SameSite=Lax, Secure в production). В базе — только хеш токена. |
| Ошибки | `{ "error": { "code": "SLOT_TAKEN", "message": "…", "details": … } }`. `code` — постоянный код для интерфейса, `message` — текст для человека. |
| Лишние поля | Неизвестное поле в теле или строке запроса — ошибка 400: опечатка не должна молча игнорироваться. |

**Коды ответа:**

| Код | Когда |
|---|---|
| 200, 201, 204 | Успех; 201 — создано, 204 — без тела |
| 400 | Неверные данные: формат, обязательные поля, несовместимые услуги, мастер не выполняет услугу. Для ошибок формы — `VALIDATION_ERROR` со списком `details.fields: [{ field, message }]` |
| 401 | Нет входа (`UNAUTHORIZED`), сессия истекла (`SESSION_EXPIRED`), неверный логин или пароль (`INVALID_CREDENTIALS`) |
| 403 | Не хватает прав: раздел администратора, чужая запись, правило 24 часов (`CHANGE_DEADLINE_PASSED`), доступ закрыт администратором (`ACCOUNT_BLOCKED`) |
| 404 | Нет такой записи, мастера, услуги или адреса |
| 409 | Конфликт: время занято (`SLOT_TAKEN`, в `details.alternatives` — свободные слоты того же дня), бронь истекла или не найдена, e-mail или телефон заняты, запись изменена другим сотрудником (`VERSION_CONFLICT`), запись уже отменена (`BOOKING_NOT_ACTIVE`) |
| 413, 415 | Слишком большое тело запроса; тело не JSON или файл не изображение |
| 429 | Слишком много запросов, неверных паролей подряд или повторный код раньше чем через минуту; заголовок `Retry-After` |
| 503 | Режим технических работ (`MAINTENANCE`); почта или SMS не настроены или не отвечают (`RECOVERY_UNAVAILABLE`, `EMAIL_UNAVAILABLE`, `SMS_UNAVAILABLE`, `DELIVERY_FAILED`) |

**Роли.** Клиент видит и меняет только свои записи. Администратор — все, без правила 24 часов и без ограничений «2 часа до визита» и «90 дней вперед». Учетная запись мастера входит, но прав пока не имеет (раздел 10.8 схемы).

## Эндпоинты

### Вход

| Метод и адрес | Кто | Что делает |
|---|---|---|
| `POST /api/auth/register` | все | Регистрация клиента: `name`, `phone` и/или `email`, `password` (8–128 символов), `pdConsent: true`, `marketingConsent`. Пароль сразу хешируется argon2id; сохраняется дата и редакция согласия (`PD_POLICY_VERSION`). Сразу открывает сессию. Занятый e-mail или телефон — 409; телефон клиента, которого записали по звонку, — 409 с подсказкой обратиться к администратору (сценарий 16: без подтверждения номера привязка не выполняется) |
| `POST /api/auth/login` | все | Вход по телефону или e-mail (`login`) и паролю, один для всех ролей. После 5 неверных паролей подряд вход закрыт на 15 минут (429) |
| `POST /api/auth/logout` | все | Закрывает сессию и снимает бронь времени пользователя, чтобы слот освободился сразу |
| `GET /api/auth/me` | вошедший | Своя учетная запись: имя, роль, телефон, e-mail, подтверждены ли они. Без хеша пароля и служебных полей |
| `POST /api/auth/password-reset/request` | все | Восстановление пароля по `login`. На e-mail приходит одноразовая ссылка `APP_URL/reset-password?token=…` (60 минут); при входе по телефону и подключенном SMS-шлюзе — код из 6 цифр (15 минут). Ответ всегда 202 — одинаковый, есть такой аккаунт или нет. Не чаще раза в минуту на аккаунт |
| `POST /api/auth/password-reset/confirm` | все | Новый пароль: `{ token, password }` по ссылке или `{ login, code, password }` по коду. Код перестает действовать после 3 неверных попыток. Все сессии пользователя закрываются; адрес, на который пришла ссылка или код, считается подтвержденным |

### Профиль

| Метод и адрес | Кто | Что делает |
|---|---|---|
| `PATCH /api/profile` | вошедший | Имя и согласие на новости (`name`, `marketingConsent`) |
| `POST /api/profile/password` | вошедший | Смена пароля: `currentPassword`, `newPassword`. Неверный текущий пароль — 403. Остальные сессии закрываются, текущая остается |
| `POST /api/profile/email` | вошедший | Новый (или неподтвержденный) e-mail: на него уходит код. Адрес занят — 409 |
| `POST /api/profile/email/confirm` | вошедший | Ввод кода: адрес записывается в профиль и отмечается подтвержденным. До кода профиль не меняется |
| `POST /api/profile/phone`, `POST /api/profile/phone/confirm` | вошедший | То же для телефона с кодом в SMS. Пока SMS-шлюз не подключен — 503: телефон меняет администратор |
| `DELETE /api/profile` | клиент | Удаление аккаунта с подтверждением паролем (`password`). Предстоящие записи отменяются, имя заменяется на «Удаленный клиент», телефон, e-mail, пароль, согласия, карточка, заметки, комментарии к записям, сессии и неопубликованные фото визитов стираются. Прошедшие визиты остаются в истории студии без связи с человеком (решение 20 схемы) |

### Студия, услуги, мастера

| Метод и адрес | Кто | Что делает |
|---|---|---|
| `GET /api/studio` | все | Название, адрес, телефон, ссылки, часовой пояс, режим работы и правила записи (шаг слотов, горизонт, 2 часа до визита, 24 часа на изменение, 10 минут брони), режим технических работ |
| `GET /api/studio/days?from=&to=` | все | Особые дни студии для календаря: закрытые дни и сокращенные часы с причиной («Санитарный день»). По умолчанию — от сегодня на горизонт записи |
| `GET /api/gallery?masterId=` | все | Галерея «Наши работы» или работы мастера: опубликованные фото с подписью, мастером и услугой |
| `GET /api/photos/:id/file` | все / администратор | Файл фото. Опубликованное доступно всем, неопубликованное — только администратору (остальным 404) |
| `GET /api/services` | все | Каталог: активные услуги по категориям с длительностью и ценами мастера и топ-мастера; к каким услугам можно добавить опцию; несовместимые пары с объяснением |
| `GET /api/masters?services=8,3:2` | все | Активные мастера. С `services` — только те, кто выполняет **все** услуги визита, и стоимость и длительность визита у каждого (цена зависит от уровня мастера). Формат `services`: номера услуг через запятую, количество — через двоеточие |
| `GET /api/masters/:id` | все | Профиль мастера: уровень, специализация, рассказ, услуги с ценой по его уровню |

### Свободное время

| Метод и адрес | Кто | Что делает |
|---|---|---|
| `GET /api/masters/:id/slots?date=…&services=…` | все | Свободное время мастера на дату студии для визита из этих услуг: `slots: [{ startsAt, endsAt }]` в UTC, режим дня (`open`, `studio_closed` с причиной, `master_off`), длительность и цена визита. Считается **при каждом запросе** из графика мастера (с изменениями на дату и режимом студии), созданных записей с уборкой после них, блокировок и чужих действующих броней; таблицы готовых слотов нет. Визит целиком помещается в рабочее время, уборка не задевает следующую запись |
| `GET /api/masters/:id/slots?date=…&bookingId=…` | владелец записи, администратор | То же для переноса: длительность и уборка берутся из записи, сама запись не считается занятым временем, цена пересчитывается только у мастера другого уровня |
| `GET /api/slots?date=…&services=…` | все | Вариант «Любой свободный мастер»: слоты всех подходящих мастеров, в каждом — `masterIds` свободных мастеров; список мастеров с ценой визита |

### Бронь времени

| Метод и адрес | Кто | Что делает |
|---|---|---|
| `POST /api/holds` | клиент, администратор | Закрепляет время на `slot_hold_min` минут (10) на время оформления. Тело: `startsAt` и `services` с `masterId` (или `masterId: null` — «Любой мастер», сервис назначит первого свободного), либо `bookingId` для переноса. В транзакции `BEGIN IMMEDIATE` удаляет истекшие брони и прежнюю бронь пользователя, заново проверяет время и создает бронь; одновременную вторую бронь на то же время база отклонит триггером. Занято — 409 с альтернативами. Ответ: мастер, цена, `expiresAt` и `secondsLeft` |
| `GET /api/holds/current` | клиент, администратор | Действующая бронь пользователя или `null`, если ее нет или она истекла |
| `DELETE /api/holds/current` | клиент, администратор | Снять бронь («Выйти из записи»): время освобождается сразу |

Истекшая бронь перестает мешать другим сразу по `expires_at`, а строки удаляются уборкой раз в минуту и при каждой новой брони.

### Записи

| Метод и адрес | Кто | Что делает |
|---|---|---|
| `POST /api/bookings` | клиент, администратор | Создает запись: `masterId`, `startsAt`, `services`, `comment`, `isAnyMaster`. Клиенту нужна его действующая бронь на то же время и услуги (иначе 409 `HOLD_NOT_FOUND`, `HOLD_EXPIRED`, `HOLD_MISMATCH`). Администратор записывает без брони клиента из базы (`clientId`) или нового клиента по имени и телефону (`newClient`). Время проверяется повторно в транзакции, бронь снимается, название, цена и длительность услуг копируются в запись |
| `GET /api/bookings?status=…&period=upcoming\|past` | клиент | Свои записи: предстоящие сверху, затем прошедшие и отмененные. У каждой — услуги, мастер, сумма, отмена с причиной, `canChange` и `changeDeadline` по правилу 24 часов |
| `GET /api/bookings/:id` | владелец, администратор | Карточка записи. Чужая запись — 403. Администратор дополнительно видит контакты клиента, время уборки, кто создал запись и историю изменений |
| `POST /api/bookings/:id/reschedule` | владелец, администратор | Перенос той же записи: `startsAt`, `masterId` (другой мастер), `reason`, `version`. Клиенту нужна бронь на перенос (`POST /api/holds` с `bookingId`) и не позднее чем за 24 часа до визита. Цена пересчитывается только у мастера другого уровня; старое и новое время, мастер и суммы попадают в историю |
| `POST /api/bookings/:id/cancel` | владелец, администратор | Отмена: `reason`, `version`; администратор указывает `by: client \| studio`. Сначала событие отмены в журнале, затем статус. Клиент — не позднее чем за 24 часа (иначе 403 с телефоном студии) |
| `POST /api/bookings/:id/status` | администратор | «Визит завершен» или «Клиент не пришел»: `status: completed \| no_show`, `reason`, `version`. Только для визита, который уже начался (иначе 409 `VISIT_NOT_STARTED`); ошибочную отметку можно поменять на другую. Отмененную запись отметить нельзя. Каждая смена — событие в истории |
| `POST /api/bookings/:id/acknowledge` | владелец | Клиент закрыл баннер «Запись отменена или перенесена студией». Баннер виден в поле `studioChange` записи (`{ type, at }` или `null`) |

`version` — номер версии записи, который видел пользователь. Если запись уже изменил другой сотрудник, ответ 409 `VERSION_CONFLICT` (экран A-S1).

### Раздел администратора

| Метод и адрес | Что делает |
|---|---|
| `GET /api/admin/bookings` | Все записи студии с контактами клиентов. Фильтры: `dateFrom`, `dateTo` (даты студии, включительно), `masterId`, `serviceId`, `clientId`, `status`, `limit` (до 500), `offset`; в ответе `total` |
| `GET /api/admin/services` | Все услуги, включая отключенные: цены, длительность, уборка, мастера, правила опции; категории и несовместимые пары |
| `POST /api/admin/services` | Новая услуга: `categoryId`, `kind` (`main` или `addon`), `name`, `durationMin`, `cleanupMin`, `priceMasterKop`, `priceTopKop`, `priceUnit`, `maxQuantity`, `isFeatured`, `sortOrder`, `isActive`, `masterIds`, `addonForServiceIds` (для опции). Цена топ-мастера не ниже цены мастера; название не повторяется без учета регистра |
| `PATCH /api/admin/services/:id` | Изменение услуги, включая `isActive: false` — отключение. Удаления нет: на услугу ссылаются записи. Созданные записи сохраняют прежние название и цену |
| `POST /api/admin/service-incompatibilities` | Пара несовместимых услуг `serviceIds: [a, b]` с объяснением для клиента |
| `DELETE /api/admin/service-incompatibilities/:a/:b` | Убрать пару |
| `GET /api/admin/masters` | Все мастера, включая отключенных: уровень, услуги, действующий и будущий недельный график |
| `POST /api/admin/masters` | Новый мастер: профиль, `level`, `serviceIds` и `schedule: { validFrom, days: [{ weekday, start, end }] }` |
| `PATCH /api/admin/masters/:id` | Изменение мастера, уровня, услуг; `isActive: false` — отключение, в ответе предстоящие записи мастера, которые нужно перенести или отменить |
| `PUT /api/admin/masters/:id/schedule` | Новый недельный график с даты (сценарий 14): текущие строки закрываются днем накануне. В ответе — действующие записи с этой даты, которые в новый график не попадают. С `dryRun: true` график не сохраняется |

**Расписание.** Каждое изменение отвечает списком `affectedBookings` — действующих записей, которые оно задевает. База их не трогает: администратор переносит или отменяет их сам. С `dryRun: true` изменение не сохраняется, а только показывает этот список (предпросмотр до сохранения).

| Метод и адрес | Что делает |
|---|---|
| `GET /api/admin/time-blocks?masterId=&from=&to=` | Блокировки мастеров за период |
| `POST /api/admin/time-blocks` | Блокировка: `masterId`, `type` (`lunch`, `personal`, `day_off`, `vacation`, `sick_leave`, `other` — для него обязателен `comment`), `startsAt`, `endsAt` в UTC. Слоты на это время пропадают сразу (сценарий 8) |
| `DELETE /api/admin/time-blocks/:id` | Удалить блокировку |
| `GET /api/admin/masters/:id/days?from=&to=` | Изменения смены мастера на даты |
| `PUT /api/admin/masters/:id/days/:date` | Рабочий день вне графика (`isWorking: true`, `start`, `end`) или выходной (`isWorking: false`). Открыть день, когда закрыта студия, нельзя — студия важнее мастера |
| `DELETE /api/admin/masters/:id/days/:date` | Убрать изменение: день снова по недельному графику |
| `GET /api/admin/studio-days?from=&to=` | Особые дни студии с автором |
| `PUT /api/admin/studio-days/:date` | Особый день для всех мастеров: закрыта (`isOpen: false`) или особые часы (`isOpen: true`, `open`, `close`), `reason` видна клиентам. Прошедший день — 400 |
| `DELETE /api/admin/studio-days/:date` | Убрать особый день |

**Клиентская база.** Метки, статистика и любимый мастер считаются по записям при каждом запросе. Метки: «Новый» (`new`) — не больше одного завершенного визита; «Давно не приходил» (`lapsed`) — последний завершенный визит больше 90 дней назад; «Постоянный» (`regular`) — от 5 завершенных визитов. В паспорте и прототипе порогов нет, они заданы в `TAG_RULES` (`server/src/api/admin-clients.ts`).

| Метод и адрес | Что делает |
|---|---|
| `GET /api/admin/clients?search=&filter=&sort=&limit=&offset=` | Клиенты: имя, телефон, e-mail, есть ли аккаунт, число визитов, последний визит, сумма, любимый мастер, метка, черный список. Поиск по имени (без учета регистра, в том числе кириллицы), e-mail и цифрам телефона; `filter`: `new`, `regular`, `lapsed`, `blacklist`; `sort`: `name`, `lastVisit`, `visits` |
| `GET /api/admin/clients/:id` | Карточка: контакты, дата рождения, источник, «Важно», черный список с причиной и автором, статистика (визиты, отмены, неявки, первый и последний визит, сумма, средний чек), все записи с числом фото, заметки |
| `POST /api/admin/clients` | Новый клиент без учетной записи: имя, телефон, e-mail по желанию |
| `PATCH /api/admin/clients/:id` | Имя, телефон, e-mail (новый контакт — неподтвержденный), `birthDate`, `acquisitionSource`, `importantNote` |
| `PUT /api/admin/clients/:id/blacklist` | Внести в черный список, `reason` обязательна |
| `DELETE /api/admin/clients/:id/blacklist` | Убрать из черного списка |
| `POST /api/admin/clients/:id/notes` | Заметка; `masterId` — «со слов мастера» |
| `DELETE /api/admin/clients/:id/notes/:noteId` | Удалить заметку |
| `PUT /api/admin/users/:id/block` | Закрыть доступ любой учетной записи: все ее сессии закрываются сразу, вход — 403 `ACCOUNT_BLOCKED`. Свою закрыть нельзя |
| `DELETE /api/admin/users/:id/block` | Открыть доступ |

**Фото работ.** Файл передается телом запроса как есть (`Content-Type: image/jpeg`, `image/png` или `image/webp`, до 10 МБ), параметры — в строке запроса. Тип проверяется по содержимому файла, а не по заголовку. Файлы лежат в `UPLOADS_DIR`, в базе — путь.

| Метод и адрес | Что делает |
|---|---|
| `GET /api/admin/photos?bookingId=&clientId=&masterId=&published=` | Все фото, включая неопубликованные |
| `POST /api/admin/photos?bookingItemId=…&title=…` | Фото к услуге завершенного визита (незавершенного — 409) |
| `POST /api/admin/photos?masterId=…&serviceId=…&title=…` | Фото прямо в галерею |
| `PATCH /api/admin/photos/:id` | `title`, `publishConsent` (согласие клиента, только у фото с визита), `isPublished`, `sortOrder`. Фото с визита без согласия не публикуется (409 `CONSENT_REQUIRED`); отзыв согласия снимает публикацию |
| `DELETE /api/admin/photos/:id` | Удалить фото вместе с файлом |

**Настройки.** Избранные услуги для главной — `isFeatured` услуги, рассказ о мастере — `bio` мастера.

| Метод и адрес | Что делает |
|---|---|
| `GET /api/admin/settings` | Все настройки студии и режим работы по дням недели |
| `PATCH /api/admin/settings` | `studioName`, `address`, `phone`, `mapUrl`, `vkUrl`, `telegramUrl` (только `http(s)://`), `timezone` (IANA), `slotStepMin`, `bookingHorizonDays`, `minLeadMin`, `clientChangeDeadlineHours`, `slotHoldMin`, `isMaintenance` |
| `PUT /api/admin/studio-hours` | Режим работы: `days: [{ weekday, open, close }]`, дня нет в списке — студия закрыта. В ответе — предстоящие записи вне нового режима; есть `dryRun` |

## Почта и SMS

Письма с кодами и ссылками отправляет встроенный SMTP-клиент (`server/src/notify/mailer.ts`, без зависимостей): порт 465 — TLS сразу, другие порты — STARTTLS; без шифрования соединяется только с сервером на этом же компьютере. Настройки — `SMTP_*` в `server/.env`. При разработке без SMTP письма печатаются в консоль сервера. В production без SMTP восстановление пароля и смена e-mail отвечают 503.

SMS-шлюз еще не выбран: при разработке коды печатаются в консоль, в production смена телефона по SMS отвечает 503, а пароль восстанавливается по ссылке на e-mail — как в паспорте.

## Чего в API пока нет

Регистрация клиента, которого раньше записали по телефону, с привязкой прежних записей после кода из SMS (сценарий 16) — ждет SMS-шлюза; до этого привязку делает администратор. Связь учетной записи мастера с профилем и права роли «Мастер» — вместе с разделом мастера.
