# Ноготочки. Онлайн-запись

Веб-сервис онлайн-записи в бьюти-студию «Ноготочки»: клиент сам выбирает услуги, мастера, дату и время, администратор ведет каталог, мастеров, расписание и записи, мастер смотрит свое расписание. Что и зачем делает сервис — в [паспорте продукта](docs/pasport-produkta.md).

Что есть сейчас:

* **Сервер** (`server/`) — REST API на все функции паспорта: Node.js и TypeScript, база SQLite через встроенный модуль `node:sqlite`, 204 автотеста.
* **Интерфейс** (`web/`) — настоящий интерфейс по прототипу на обычных HTML, CSS и JS без сборки, адаптирован под телефон, планшет и компьютер: витрина и кабинет клиента, раздел администратора `/admin` и раздел мастера `/master`. Экраны — в разделе [«Интерфейс»](#интерфейс) ниже.
* **Тестовый интерфейс** (`web-draft/`) — черновой фронтенд без дизайна, с которого начинали проверять API. Для работы больше не нужен: все экраны всех трех ролей есть в `web/`. Оставлен как запасной способ дернуть эндпоинт руками.
* **Прототип** (`Prototype/`) — кликабельный прототип экранов из Claude Design, открывается в браузере как обычные HTML-файлы.

Отдельной формы входа у сотрудников нет: вход общий, `login.html`, а страницы разделов отдает сервер API после проверки роли — гостя уводит на вход, чужой роли отвечает 403.

## Что понадобится

| Что | Версия | Зачем |
|---|---|---|
| [Node.js](https://nodejs.org/) вместе с npm | **24.7 или новее**, лучше последняя 24.x (LTS) | Сервер и оба интерфейса. Версия ниже 24.7 не подойдет: в ней нет встроенного argon2 для паролей, и команды откажутся запускаться |
| [Git](https://git-scm.com/downloads) | любая | Скачать код |
| Доступ к репозиторию на GitHub | — | Репозиторий закрытый: попросите владельца добавить ваш аккаунт GitHub |
| Браузер | любой современный | Открыть интерфейс |

Больше ничего ставить не нужно: база данных — файл, который создаст сам сервер; компилятор, Python и Docker не нужны.

## Установка

Команды ниже работают в PowerShell (Windows), Терминале (macOS) и bash (Linux). Где для Windows команда другая, это сказано отдельно.

### 1. Установите Node.js и Git

* **Windows.** Скачайте установщик Node.js с [nodejs.org](https://nodejs.org/) — кнопка с пометкой LTS, версия 24.x — и установщик Git с [git-scm.com](https://git-scm.com/downloads). Все параметры установщиков можно оставить по умолчанию. После установки **закройте и заново откройте** PowerShell, иначе он не увидит новые программы.
* **macOS.** Установщик Node.js с [nodejs.org](https://nodejs.org/); Git предложит поставить сама система при первом вызове `git`.
* **Linux.** Node.js 24 — по [инструкции для вашего дистрибутива](https://nodejs.org/en/download): в стандартных репозиториях обычно лежит устаревшая версия. Git — пакетом `git`.

Проверьте:

```bash
node -v
npm -v
git --version
```

`node -v` должен показать `v24.7.0` или новее (например, `v24.19.0`).

> **Windows: «выполнение сценариев отключено в этой системе».** Если PowerShell отвечает на `npm -v` такой ошибкой, выполните один раз
> `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`, ответьте `Y` и повторите команду. Другой вариант — запускать команды в «Командной строке» (cmd) вместо PowerShell.

### 2. Скачайте код

```bash
git clone https://github.com/kostik8080/nogotochki_service.git
cd nogotochki_service
```

Git попросит войти в GitHub — репозиторий закрытый. Если у вас настроен SSH-ключ, можно клонировать по адресу `git@github.com:kostik8080/nogotochki_service.git`.

### 3. Установите зависимости сервера

```bash
cd server
npm install
```

Если npm остановится с ошибкой `EBADENGINE`, у вас слишком старый Node.js — вернитесь к шагу 1.

### 4. Создайте файл настроек `server/.env`

Скопируйте шаблон:

```bash
cp .env.example .env
```

(в «Командной строке» Windows — `copy .env.example .env`)

Откройте `server/.env` в любом текстовом редакторе (Windows: `notepad .env`) и придумайте пароли для трех тестовых учетных записей — **не короче 8 символов**:

```
SEED_ADMIN_PASSWORD=придумайте-пароль-администратора
SEED_MASTER_PASSWORD=придумайте-пароль-мастера
SEED_CLIENT_PASSWORD=придумайте-пароль-клиентки
```

Остальные строки не трогайте: для локального запуска подходят значения по умолчанию. Файл `.env` в git не попадает.

Если хотите проверить кнопку «Войти через Яндекс», добавьте в `server/.env` идентификатор и секрет приложения с https://oauth.yandex.ru — что это такое, читайте ниже в разделе «Вход через Яндекс»:

```
YANDEX_CLIENT_ID=идентификатор-приложения
YANDEX_CLIENT_SECRET=секрет-приложения
```

### 5. Создайте базу с тестовыми данными

```bash
npm run db:reset
```

Команда создаст файл базы `server/data/nogotochki.db`, применит все миграции и загрузит тестовые данные: студию, 3 мастеров, 14 услуг, график, несколько записей и учетные записи с паролями из шага 4. В конце появится таблица добавленных строк и строка «Сценарные данные … добавлены».

Если команда пишет «Задайте в server/.env пароли не короче 8 символов», вернитесь к шагу 4.

## Запуск

### Все сразу одной командой

Из папки проекта:

```bash
node tools/dev.mjs
```

Запустятся сервер API (порт 3000) и интерфейс (порт 8090) в одном окне. Строки вывода помечены, чьи они: `[api]` и `[web]`. Откройте **http://127.0.0.1:8090**. `Ctrl+C` останавливает оба.

С ключом `--draft` поднимется еще и черновой интерфейс `web-draft/` (порт 5173, нужен `npm install` в этой папке). Для работы он не нужен — только чтобы дернуть эндпоинт руками:

```bash
node tools/dev.mjs --draft
```

Если порт занят, команда прямо скажет какой и чем: значит, сервис уже запущен в другом окне — закройте его и повторите.

Дальше — тот же запуск по частям, в отдельных окнах. Он нужен, когда хочется перезапускать сервер и интерфейс по отдельности или видеть их вывод раздельно.

### Окно 1: сервер API

```bash
cd server
npm start
```

Сервер пишет, на каком адресе работает, и остается запущенным — окно не закрывайте. Проверка: откройте в браузере http://localhost:3000/api/studio — должен прийти JSON с названием и адресом студии.

### Окно 2: интерфейс

Из папки проекта:

```bash
node tools/web-dev-server.mjs
```

Откройте **http://127.0.0.1:8090** — лендинг студии. `npm install` не нужен: сервер отдает файлы из `web/` как есть, без сборки, и передает запросы `/api` серверу API на порту 3000, поэтому вход работает без CORS. Другие порты: `PORT=8091 API_URL=http://127.0.0.1:3001 node tools/web-dev-server.mjs` (в PowerShell переменные задаются через `$env:PORT="8091"`).

### Окно 3 (по желанию): черновой интерфейс для проверки API

Разделы администратора и мастера есть в основном интерфейсе — это окно нужно, только если хочется дернуть эндпоинт руками. Из папки проекта:

```bash
cd web-draft
npm install
npm run dev
```

`npm install` нужен только при первом запуске. Откройте **http://127.0.0.1:5173** — должна открыться страница входа «Ноготочки · тест API».

Открывайте именно `127.0.0.1`, а не `localhost`: интерфейс слушает только этот адрес, и в некоторых браузерах `localhost:5173` не откроется.

### Вход

| Роль | Логин | Пароль | Где и что посмотреть |
|---|---|---|---|
| Клиентка | `maria@example.com` | `SEED_CLIENT_PASSWORD` из `server/.env` | Запись, «Мои записи», история, профиль |
| Администратор | `admin@example.com` | `SEED_ADMIN_PASSWORD` | После входа открывается `/admin`: записи, заявки, клиенты, услуги, мастера, настройки |
| Мастер | `anna@example.com` | `SEED_MASTER_PASSWORD` | После входа открывается `/master`: свое расписание и свои заявки |

Вход общий для всех трех ролей — форма «Войти» на 8090; куда вести после входа, решает роль учетной записи. Нового клиента можно зарегистрировать на странице «Регистрация». Что проверяет каждая страница чернового интерфейса — в [web-draft/README.md](web-draft/README.md).

### Вход через Яндекс

На страницах «Вход» и «Регистрация» есть кнопка **«Войти через Яндекс»**. По нажатию браузер уходит на страницу согласия Яндекса, а после согласия возвращается на страницу входа с одноразовым кодом. По этому коду сервер сам, без браузера, забирает у Яндекса адрес почты, имя и фамилию, находит человека по адресу (или заводит нового клиента) и открывает свою сессию. Токен Яндекса нигде не сохраняется.

Чтобы кнопка работала, нужно приложение на https://oauth.yandex.ru:

* права — доступ к адресу почты, имени и фамилии, больше ничего;
* адрес возврата (Redirect URI) — ровно `APP_URL` + `/login.html`, например `https://buty.topbrohuman.ru/login.html`, а при разработке `http://127.0.0.1:8090/login.html`;
* идентификатор и секрет приложения задаются переменными `YANDEX_CLIENT_ID` и `YANDEX_CLIENT_SECRET`. В коде и в репозитории их нет.

Пока эти переменные не заданы, кнопка отвечает «Вход через Яндекс сейчас недоступен», а вход по телефону или e-mail и паролю работает как обычно. Если человек на экране согласия нажмет «Отмена», Яндекс вернет его на страницу входа, и там появится сообщение, что вход не завершен.

### Остановка

В каждом окне нажмите `Ctrl+C`. База остается в файле `server/data/nogotochki.db`; при следующем запуске повторите только `npm start` и запуск интерфейсов.

## Частые действия

| Что | Команда (из `server/`) |
|---|---|
| Вернуть базу к исходным тестовым данным (удалит все, что вы создали) | Остановите сервер, затем `npm run db:reset` |
| Запустить автотесты | `npm test` — работают на отдельной базе в памяти, вашу базу не трогают; `.env` для них не нужен |
| Проверить типы TypeScript | `npm run typecheck` (в `web-draft/` — тоже `npm run typecheck`) |
| Сервер с перезапуском при изменении кода | `npm run dev` вместо `npm start` |
| Запустить сервер и интерфейс одной командой | Из папки проекта: `node tools/dev.mjs` (с `--draft` — и черновой интерфейс) |
| Посмотреть прототип (для запуска сервиса не нужен) | Из папки проекта: `python -m http.server 8765 --directory Prototype`, затем http://localhost:8765 и файл «Прототип - Ноготочки.dc.html». Нужен [Python](https://www.python.org/downloads/) 3; страницы прототипа загружают соседние файлы, поэтому открывать их двойным щелчком ненадежно |

Все команды сервера, сборка и выкладка на хостинг — в [server/README.md](server/README.md).

## Если что-то не работает

| Что видно | Причина и что делать |
|---|---|
| `EBADENGINE` при `npm install` или «Нужен Node.js 24.7.0 или новее» | Старый Node.js. Установите 24.x, закройте и откройте терминал, проверьте `node -v` |
| PowerShell: «выполнение сценариев отключено» | См. примечание в шаге 1 или используйте «Командную строку» |
| `npm start`: «В базе не применены миграции» | Не выполнен шаг 5: `npm run db:reset`. Сервер советует `db:migrate` — для локального запуска не следуйте этому совету: он создаст пустую базу без услуг, мастеров и учетных записей |
| Интерфейс пишет «Студия в режиме технических работ», каталог и мастера пустые, войти не получается | База создана без тестовых данных: `db:migrate` вместо `db:reset` или `db:reset` оборвался на ошибке про пароли. Заполните `server/.env` (шаг 4), остановите сервер и выполните `npm run db:reset` |
| `db:reset` или `db:seed`: «Задайте в server/.env пароли…» | Не создан `server/.env` или в нем пустые `SEED_*` — шаг 4 |
| `EADDRINUSE`, порт 3000, 8090 или 5173 занят | Сервер или интерфейс уже запущен в другом окне — закройте его (`Ctrl+C`). Порт API можно сменить строкой `PORT=` в `server/.env`, но тогда передайте новый адрес интерфейсу (`API_URL=`) и поправьте адрес `/api` в `web-draft/vite.config.ts` |
| Интерфейс открылся, но везде «Сервер API не отвечает» | Не запущен сервер (окно 1) |
| `localhost:5173` не открывается | Откройте http://127.0.0.1:5173 |
| Вход не проходит под тестовой учетной записью | Пароль берется из `server/.env` на момент `db:reset`. Если меняли `.env` позже — повторите `npm run db:reset`. После 5 неверных паролей вход закрыт на 15 минут |
| `db:reset` падает с ошибкой доступа к файлу базы (Windows) | Файл держит запущенный сервер — остановите его и повторите |
| `ExperimentalWarning: SQLite is an experimental feature` | Не ошибка, в ранних выпусках Node 24 это просто предупреждение |
